# ts-rs-prism

Project site for [tsc-rs](https://github.com/benfavre/ts-rs), served at
https://ts-rs.bext.dev by the bext masquerade (root mode, vhost
`/etc/nginx/sites-enabled/ts-rs.bext.dev.conf`, certbot lineage `ts-rs.bext.dev`).

## Layout

| Path | What |
|---|---|
| `src/app/` | Routes: `/`, `/conformance`, `/progress`, `/playground`, `/docs`, `/docs/[slug]`, plus `not-found.tsx` and the `[...rest]` catch-all that answers 404. Thin files that wire sections together |
| `src/sections/` | Page sections, built as HTML strings (opaque to the PRISM fold pass) |
| `src/lib/site.ts` | Links, navigation and the accessors for **every number shown on the site** |
| `src/lib/repo.generated.ts` | GENERATED by `scripts/sync.ts`: version, published metrics snapshot, the wave log |
| `src/lib/theme.ts`, `theme-extra.ts` | The whole stylesheet (light and dark), inlined by the layout |
| `src/lib/docs-nav.ts` | Docs sidebar, landing cards, pager order and page titles |
| `src/lib/markdown.ts`, `highlight.ts` | Markdown rendering and server-side syntax highlighting |
| `content/docs/*.md` | Docs pages, read at render time |
| `public/` | `site.js` (nav, theme, search, chart hover), `playground.js`, `highlight.js` (built), fonts, the wasm package, and the generated `search-index.json`, `sitemap.xml`, `llms.txt` |
| `scripts/sync.ts` | Regenerates everything derived from the tsc-rs checkout and from the docs |
| `scripts/build-wasm.sh` | Rebuilds `public/playground/pkg` from a tsc-rs checkout |

## Updating

- **The repository moved (new waves, new README numbers, new version)**: `git -C ~/ts-rs-public pull`,
  then `bun scripts/sync.ts`. Push the measured code and `docs/compatibility-metrics.json`
  to **https://github.com/benfavre/ts-rs on main first**. The sync requires this
  checkout's HEAD to match public main and reads committed inputs with `git show`.
  It validates snapshot counts and both diagnostic wave totals before writing.
  All metric displays, documentation placeholders and search use that snapshot.
- **A docs page**: edit or add `content/docs/<slug>.md`. For a new page also add it to
  `src/lib/docs-nav.ts`. Then `bun scripts/sync.ts` (search index, sitemap, llms.txt).
  Slugs are single-segment: the root `[...rest]` catch-all shadows a nested catch-all.
- **The playground compiler**: `scripts/build-wasm.sh ~/ts-rs-public`. The package URL is
  cache-busted with the version from the sync.
- **Wasm sidecars**: `scripts/build-wasm.sh` also writes verified `.br` and `.gz` files next to the wasm
  (`scripts/precompress.mjs`); the server serves them only while they are newer than the source.
- **Accessibility**: the pages pass axe (WCAG 2 A and AA plus best practices) in both themes. Keep text
  colours on the `--muted` and `--faint` tokens, which were tuned for 4.5:1 on every surface.
- **The highlighter**: after editing `src/lib/highlight.ts`, `bun run build:client` rebuilds
  `public/highlight.js` for the playground.
- **Scripts in `public/`**: bump the `?v=` on the script tag (`src/app/layout.tsx`,
  `src/app/playground/page.tsx`, the import in `public/playground.js`).
- **Removing a route file** briefly breaks every route (the bundle still requires it). Do it
  in a quiet moment and check the site afterwards.

The source watcher reloads changes in the configured `watch_dirs`. Copy a
complete reviewed batch, then fetch the public pages and verify their
`data-build` attribute and visible metrics match the published source.
Pages use ISR caching, so a successful file copy alone is not deployment
verification. The September 30 update refreshed through the watcher without a
service restart. Administrative cache invalidation requires authentication;
the old unauthenticated SDK/purge examples return HTTP 401 on this host.

## Authoring rules

- Source files stay ASCII. No em dash in copy.
- `theme.ts` and `theme-extra.ts` hold template literals: no backtick, no dollar-brace, no backslash inside them.
- Every colour goes through a token so both themes work; chart series colours were checked with
  the dataviz palette validator against both surfaces.
- Claims about tsc-rs must be checked against the repository or by running the binary. The home
  page samples and the docs output samples are real compiler output.

## Source and runtime

The reviewed source lives in `website/` in the public tsc-rs repository.
This is a PRISM application for the bext runtime; `@bext-stack/framework` is
provided by the bext workspace. It is not a standalone React/Next.js app.
Install the declared development dependencies in that environment to run
`bun run typecheck`. `src/jsx.d.ts` gives PRISM HTML elements their React JSX
prop types without adding a React runtime to the page.

Generated metrics/search/feed files, compiled JavaScript, the WASM package,
node_modules, caches and compressed sidecars are not committed. After the
source and metrics are pushed to public main, run `bun scripts/sync.ts` to
regenerate content from that exact published commit, then copy reviewed
source and generated outputs into the live PRISM site. Preserve the existing
WASM package unless explicitly rebuilding it with `scripts/build-wasm.sh`.
For a new installation, `bun run build:client` supplies `public/highlight.js`.
